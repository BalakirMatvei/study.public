Основной примитив синхронизации - **блокировки(locks)** 
Lock можно сравнить с кабинкой, пока один поток **работает с общим для всех изменяемым объектом** второй не может работать с ним и ждет "снаружи кабинки" 
****
Что бы использовать эти блокировки нужно
```python
import time  
from threading import Thread  
  
class Worker(threading.Thread):  
  
    def __init__(self, name, otdyx, time_list, lock, *args, **kwargs):  
        super(Worker, self).__init__()  
        self.name = name  
        self.otdyx = otdyx  
        self.time_list = time_list  
        self.lock = lock  
  
    def run(self):  
        for i in range(1, 6):  
            print(f'{self.name}:     day {i}', flush=True) 
            time.sleep(self.otdyx)  
            self.lock.acquire()#закрыть "кабинку"
                self.time_list.append(f'{self.name} day {i} done')#действие в кабинке
	        self.lock.release()#открыть "кабинку"
        print(f'{self.name} is done')
        
worker_names = ['Ivan', 'Kolya', 'Slava', 'Ruslan', 'Arseniy']

lock = threading.Lock()

workers = [Worker(name=name, otdyx=0.8, time_list=global_time_list, lock=lock) for name in worker_names]

for worker in workers:  
    worker.start()  
for worker in workers:  
    worker.join()  
    
print('\n')  

for i in global_time_list:  
    print(f'[{i}]', end = '\n\n')
```
Но если в синхронном потоке("в кабинке") произойдет ошибка, то он не откроет `lock` и остальные потоки не смогут работать с этим объектом. (**блокировку нужно снимать ВСЕГДА**)
Что бы он открылся в любом случае можно использовать контекстный менеджер(вместо тех 3х строк):
```python
with self.lock:  
    self.time_list.append(f'{self.name} day {i} done')
```
****
Блокировки могут быть вложенными: ^1fcb11
```python
with self.lock:  
    self.list1.append(var1)
    with self.lock:
	    self.list2.append(var2)
```
Что бы это работало вместо `Lock()` нужно использовать `RLock`
```python
lock = threading.RLock()
```
